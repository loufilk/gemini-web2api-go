# ChuanAPI Gemini 模型修复：验证、部署与回退

候选版本：`4.28.1+chuanapi.models2`。基于上游 v4.28.1（`2ce99cfe8862baea8d10fd63c6ffe0c0c80a827e`），继续保留 Hydrogen、Carbon 的现网名称。本文不执行部署。New API #157 现状保持不变：Ultra 分组只启用 `gemini-4-hydrogen`、`gemini-4-carbon`。

## 行为与配置

- 每个启用账户独立读取可选模型目录。型号、Hex、Mode 和思考档不从首次请求名或旧槽位猜测。仅目录中存在的型号才可被选中；思考策略只补充档位，不能产生目录中没有的型号。列表只汇总已发现的能力；冷启动或目录无法确认时，未确认的模型可能暂时不出现在列表。
- 目录有效缓存 5 分钟；短暂网络错误、429 或 5xx 可继续使用最长 15 分钟的已确认快照。登录/结构失败不保留旧快照，失败刷新限频；调用方取消不会清空其他请求共享的有效快照。即使用旧快照，生成仍须核验返回型号。
- `gemini-3.7-flash`、`gemini-3.8-flash`（及 thinking 变体）是输入兼容名，输出与计费归类应以 Hydrogen 正名为准。Argon 和 Carbon 不互为别名。账号目录中还有 Argon 的部署可以保留它，否则请求返回 `model_unavailable`。保护同时覆盖 `gemini-3.1-pro` 及 thinking 变体。
- 非流式未确认/不匹配通常为 502（`model_identity_unverified` / `model_identity_mismatch`）；明确回落到 Flash-Lite 走已有 `model_downgraded`、账号/模型冷却和未输出后的择号。目录不认识是 404；无法读取目录时是 503。其他型号不使用本修复的强制目录门禁。
- 先缓冲尚未核验的正文和思考内容；匹配才放行。15 秒保活可以先开流；此后 HTTP 头已经是 200，错误通过协议的**失败终态**传递，不能当作成功或根据 HTTP 状态盲目重放。若后续帧报别的型号，同一请求失败，不拼接新的生成内容。
- 可调参数：`request_timeout_sec` 是上游一次生成总预算；`first_frame_timeout_sec`、`stream_idle_timeout_sec` 独立限制首个有效内容帧和帧间空闲，默认 0（不单独限制）。`stream_keepalive_sec=15` 只作用于客户端连接，不延长任一超时。配置 180 秒不能覆盖用户观察到的 194 秒；隔离验收可先用 240 秒并把外层代理和客户端预算调高。进程记录客户端取消（499）、客户端截止、上游首帧/空闲/总时限分别归类。生成提交后连接中断、超时、缺少内容或不确定失败不再按旧重试参数重新生成。明确 XSRF 拒绝的准备修复，以及正文尚未输出时已证实的降级换号，与不确定执行不同。
- 新旧传输都受模型确认和调用方 context 约束；WebChannel 不改变权限。原生多轮仍用旧传输；目录提供且新版未验证的另一种头布局，在提交前走旧传输，不是失败后重发。同步文本主生成不代表异步视频、附件传输、媒体产物下载或远端服务本身都能立即取消。

## 隔离验收

1. 固定 fork 开发分支的候选提交，记录 `git rev-parse HEAD`、Go 1.26.8 版本和源码树；在独立数据目录执行 `go test -count=1 ./...`、`go vet ./...`、`go build ./...`。模型发现、HTTP/流、超时、请求元数据相关测试另用 `-race`。视频现有 race 是否与基线一同复现应单独记录。
2. 只从该 SHA 构建测试镜像，例如 `docker build -t gemini-web2api:models2-local .`。记录镜像 ID / 发布后的不可变 digest。数据库新增字段是加列；候选先在独立数据库验证。切换前备份现网数据库、镜像和配置，不能把构建标签当成 digest。
3. 无真实账号时用合成目录与响应帧验 Hydrogen、Carbon、Argon 权限差异、旧名、Flash-Lite 降级、缺失和冲突自报、两种传输的帧口径、SSE 终态、客户端断开和未知状态不重放。还要走 New API 类客户端，确认开流后收到错误时不结算成成功请求、不假造 usage。
4. 另获授权后，在非生产环境逐个请求 Hydrogen 与 Carbon 的流式/非流式，Argon 只在独立可选目录确实存在的账号上测试。发送前后按隔离实例的请求日志行 ID 轮询（异步写入）。比对 `requested_model`、`canonical_model`、`actual_model`、`actual_model_verified`、`account_id`、`account_label`、代理、首字节、总耗时、`retry_count`、`failure_class` 和终态；不要采集或提交 Cookie、API Key、管理令牌、代理密码及未脱敏原始报文。
5. 非生产长流目标：模拟 165 秒、194 秒及超过预算三种场景，并观察 15 秒保活、首个有效正文、完成/取消状态；客户端提前断开后不应再发第二个生成请求。遮蔽令牌的账户权限、当前模型映射与真实延迟只能由获准实测证实。用户既有两账号结果不等于本候选已经在这些账号运行。

## 手动回退

回退目标是现网已知自定义版本 `4.28.1+core.models1` 的**实际镜像 digest**，不是官方 v4.28.1 或 `latest`。切换前由现场确认保留该镜像可用，记录有效 15 秒保活、应用/网关超时配置和数据备份。

若出现模型冒名、流终态被误判、已提交却被自动重放、延迟或冷启动目录回归：先排空并隔离候选流量，再恢复已验证的旧镜像和配置。保留新列，不手工破坏性降级表结构；老镜像能否读取当前数据须在隔离环境确认。需要恢复备份时先处理切换期间的增量数据。重启后核对运行镜像 digest、健康状态、#157 原本两模型及实际型号。没有验收通过前不改 #157 的模型或分组。
